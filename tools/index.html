Tools with a reason to exist.

Flowglass has a functioning, public local-first alpha. The remaining four entries are concept-stage briefs; none is a commercial release or independently validated production system.

01 / Automation intelligence

Working browser alpha · v0.1 · Public demo

Flowglass

See the system behind the screen.

Flowglass is now a working, local-first dependency graph editor. Add components and connections, drag nodes, trace upstream and downstream reachability, detect missing documentation and review loops, then export a change-impact report.

  • Editable interactive dependency maps
  • Multi-hop impact paths and cyclic-group detection
  • JSON import/export and Markdown review reports
Open the working Flowglass alpha ↗

No tenant connection, live system scanning, or cloud project storage. Runs entirely in your browser on synthetic or user-supplied graph data.

TRIGGERForm submitted

Design illustration · Not a product screenshot
Alpha capabilities, constraints & next development gate
  1. Load the included synthetic sample, import a graph, or create an empty project
  2. Edit nodes, connections, metadata and spatial layout
  3. Inspect downstream and upstream paths, documentation gaps, isolated nodes and cycles
  4. Export project JSON or a Markdown change-impact report

Known limitations: Graphs are manually modeled or imported in Flowglass schema v1; no Power Automate or SharePoint discovery. Project storage is local to the current browser. Next gate: read-only support for exported solution metadata and human-validated regression scenarios.

02 / Evidence & document integrity

In development · Requirements & UX

Proofline

Know what a claim rests on.

Proofline is an evidence-linked review system for policies, specifications, proposals, and long-form project documentation. Instead of trusting the newest paragraph, reviewers can inspect where a statement came from, what changed, and whether its support has gone stale.

  • Claim-to-source traceability
  • Decision and revision ledgers
  • Contradiction and stale-source flags
01 CLAIM⤷ SOURCE / 003⤷ DECISION / A12SUPPORTED BY EVIDENCE
Design illustration · Not a product screenshot
Planned workflow & next development gate
  1. Register source documents and decisions
  2. Link claims to exact supporting passages
  3. Compare revisions against accepted decisions
  4. Generate an audit report with unresolved issues

Next validation gate: Prototype a source-anchored issue register and assess false-positive rates with human review.

03 / Creative production preflight

In development · Preflight specification

Printflight

Catch the mistake before the press does.

Printflight is a planned desktop-oriented QA utility for tabletop card decks, packaging, printable play aids, and illustrated sourcebooks. It focuses on repeatable checks—not replacing human art direction or printer-specific production approval.

  • Trim, bleed, and safe-zone validation
  • Card inventory and face/back pairing
  • Image quality, fonts, and export checks
TRIMSAFE ZONEBLEED · MARGINS · ASSETS
Design illustration · Not a product screenshot
Planned workflow & next development gate
  1. Load a print manifest and asset directory
  2. Check measured dimensions, resolutions, and file coverage
  3. Flag potential collisions with bleed or safe zones
  4. Produce a printer-facing preflight report

Next validation gate: Test checks against representative printer specifications and controlled sample decks.

04 / Narrative continuity

In development · Data model design

Lorelock

Let the world change without losing the truth.

Lorelock is a structured continuity workspace for tabletop campaigns, fiction, sourcebooks, and branching narrative projects. It distinguishes author-approved canon, in-world claims, proposals, and spoilers while tracking people, locations, rules, and chronology.

  • Canon and provenance labels
  • Character, place, and relationship graphs
  • Timeline and contradiction review
CANONEVENTPERSONRULE
Design illustration · Not a product screenshot
Planned workflow & next development gate
  1. Establish canonical references and protected facts
  2. Record scene outcomes, NPC changes, and rules versions
  3. Compare new text with established continuity
  4. Approve or reject changes with an explicit history

Next validation gate: Build a small, testable continuity schema around one fictional setting.

05 / Operational knowledge

In development · Interaction design

Handoff Atlas

Make the next step obvious.

Handoff Atlas is a planned guided-procedure and troubleshooting application for teams managing intricate workflows. Its goal is to turn scattered notes, exceptions, escalation paths, and checklist logic into clear, versioned operational playbooks.

  • Branching procedures and decision trees
  • Escalation and exception pathways
  • Versioned runbooks and handoff summaries

Planned workflow & next development gate
  1. Create a procedure from approved steps and conditions
  2. Define branches, cautions, and evidence requirements
  3. Guide an operator through the correct route
  4. Generate a transparent handoff and revision record

Next validation gate: User-test one non-sensitive procedure with first-time operators.

Development philosophy

No feature list
without a use case.

01 / TRACEABILITY

Show the source.

Critical decisions must point back to evidence, authorized rules, or visible assumptions.

02 / CONTROL

Keep the operator in charge.

Assist with review and execution without silently substituting an automated decision.

03 / VERIFICATION

Prove it works.

Move beyond interface concepts only after validating workflows, test data and failure handling.

Early-stage / Collaboration

Build the right thing.

Flowglass has an interactive alpha that can be used now. Proofline, Printflight, Lorelock and Handoff Atlas remain design concepts. No commercial availability or production reliability is implied.
